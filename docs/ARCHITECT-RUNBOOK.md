# Architect Runbook

The architect is the semantic authority for LooksWise implementation and the only merge authority.

Before approving a Work Item, verify:

- the implementation targets the frozen Architecture Version referenced by the Work Item;
- acceptance criteria have traceable evidence;
- provider/model integrations remain behind capability/provider adapters;
- Look/Transformation authority is not replaced by prompt-only logic;
- appearance, simulation, opinion, booking/purchase and real-world outcome states remain distinct;
- social validation permissions are enforced server-side;
- gender-restricted opinion controls are consent/visibility controls, not claims about objective attractiveness;
- medical-aesthetic functionality remains isolated from ordinary consumer transformations;
- high-fidelity promises match the evidence tier of the Reality Engine;
- no Work Item scope has silently expanded.

If architecture is inadequate, issue an Architecture Change Request. Do not patch the frozen baseline inside an implementation PR.
