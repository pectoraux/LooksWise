## Implementation constraints
- Do not modify frozen architecture documents.
- Implement only within the declared change surfaces unless an approved Architecture Change Request changes the baseline.
- Do not introduce provider/model coupling into domain modules.
- Preserve consent, authorization, provenance and versioning semantics.
- Add objective evidence for each acceptance criterion.
- One Work Item per branch/PR.
- Do not self-approve or merge.

## Definition of done
- all dependencies are satisfied;
- all listed requirements are implemented;
- every listed acceptance criterion has objective evidence;
- required automated verification passes;
- no architecture lock invariant is violated;
- PR is opened with Work Item, requirements, surfaces, verification and evidence explicitly identified;
- implementation stops at the architect review boundary.

## Out of scope
